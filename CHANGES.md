# SynapseCS Upgrade Log (CHANGES.md)

This document provides a plain-English explanation of all architectural, diagnostic, and functional changes made to SynapseCS across Part A, Part B, and Part C.

## 🔍 Part A: Animation Diagnosis & Root-Cause Tracer Engine

### 1. Diagnosis First (A1)
- **Built `/debug.html`:** A self-contained, browser-based diagnostic test harness that automatically simulates every question's animation from start to finish. It tests renderer validity, step counts, state object contracts, and pointer bounds.
- **Built `/tools/validate.js`:** A command-line validation script using plain Node.js (no npm packages required) to perform the exact same checks.
- **Initial Diagnosis Finding:** Out of 62 questions, 61 passed and 1 failed (`recent-counter` in Queue & Deque).
  - *Root Cause:* The static `animationSteps` for `recent-counter` placed raw timestamp values (`t: 1`, `t: 100`, `t: 3001`, `t: 3002`) into the pointer dictionary rather than valid element indices within the queue bounds `[0..length-1]`.
  - In addition, hand-writing animation step arrays was fundamentally brittle and prone to pointer index drift whenever code or input changed.

### 2. Fixing the Root Cause with Algorithmic Tracers (A2)
- **Created `/js/tracers/` Engine:**
  - Instead of hand-written static animation steps, we authored reference solutions in JavaScript wrapped in an immutable tracer engine (`tracer-core.js`).
  - Implemented topic tracers for all 62 questions:
    - `js/tracers/linked-list.js` (18 questions)
    - `js/tracers/stack.js` (10 questions)
    - `js/tracers/queue.js` (9 questions, with pointer index bounds fixed)
    - `js/tracers/arrays-strings.js` (9 questions)
    - `js/tracers/hashing.js` (9 questions)
    - `js/tracers/trees.js` (7 questions)
  - Each step dynamically records a semantic code tag (e.g., `init`, `alloc`, `flip`, `advance`, `loop`, `mutate`), a plain-English explanation, a deep copy of the visual state, and valid pointers. Because the steps are generated by executing the real algorithm, they are mathematically guaranteed not to drift.
- **Defined Renderer State Contracts (`/js/renderers/CONTRACTS.md`):**
  - Specified normative schemas for all 12 visualizer renderers: `array`, `linked-list`, `doubly-linked-list`, `stack`, `queue`, `tree`, `graph`, `hash-table`, `grid`, `dp-table`, `heap`, `trie`.
  - Upgraded `/js/animator.js` to validate incoming states. If any state violates the contract, instead of crashing or showing a blank canvas, it renders a bold Neo-Brutalist error callout with the error reason and a formatted JSON dump.
- **Interactive Controls & Custom Inputs:**
  - Fully enabled Play, Pause (with spacebar shortcut), Step Forward (Right Arrow), Step Back (Left Arrow, replaying clean deep-cloned snapshots), Reset (Key R), Speed Slider, and timeline scrubber.
  - Added live custom user input: users can enter custom arrays or values into the workbench, validate within bounds (maximum 25 elements to prevent browser hangs), run the reference tracer, and watch the animation re-execute in real-time.

## 🌐 Part B: Language Selection Flow & Data Separation

### 1. User Experience & Routing Flow (B1)
- **Language Picker Page (`#/languages`):**
  - The "Start Learning" button opens a language picker showcasing big Neo-Brutalist cards for all 7 languages: **Python**, **Java**, **C++**, **JavaScript**, **C**, **Go**, and **Rust**.
  - Each card displays the language logo, file extension badge, custom color token, one-line summary, and live question counts (e.g., "62 questions available / 0 completed").
  - Languages without active code yet (C, Go, Rust) are displayed with a "Coming soon" badge and locked in a disabled state (preventing dead links).
- **Persistent Selection & Nav Button:**
  - The user's chosen language is saved in `localStorage`. Returning users skip the picker and go straight to their language track.
  - A prominent "Change ⇄" button with the active language badge is placed in the navigation bar to allow returning to the picker at any time.
  - Learning progress is tracked independently per language (`synapse_progress_<lang>`).
- **Disk-Friendly Hash Routing:**
  - Implemented hash routing so the entire app works seamlessly offline from disk via `file://`:
    - `#/` → Home page
    - `#/languages` → Language picker
    - `#/learn/:lang` → Language track home with quickstart mini lesson
    - `#/learn/:lang/:topic` → Topic view filtered for that language
    - `#/learn/:lang/:topic/:qid` → Direct deep link to specific question
    - `#/progress` → Dedicated progress analytics
    - Unknown routes → Friendly 404 Not Found screen with a button back to languages.

### 2. Architecture & Data Separation (B2 & B3)
- **Language-Neutral Question Catalog (`/data/questions/<topic>.js`):**
  - Contains problem statements, constraints, examples, difficulty, LeetCode links, algorithmic approach ideas, time/space complexities, common mistakes, tracer names, and sample inputs.
  - Free from language-specific code strings or hardcoded line numbers.
- **Language-Specific Implementations (`/data/languages/<lang>/<topic>.js`):**
  - Fully separated folders for `python`, `java`, `cpp`, and `javascript`.
  - Every code line is broken down with a semantic tag (`init`, `loop`, `pointer`, `mutate`, `return`, `def`).
  - Code explanations and animation steps reference tags, not volatile line numbers.
  - Genuinely authored language notes for memory layout and idioms (e.g., Python reference binding, Java garbage collection, C++ value semantics vs pointers, V8 JIT optimization).
- **Language Metadata (`/data/languages/<lang>/meta.js`):**
  - Contains language name, icon, color, file extension, and a "Hello World + How to run it" mini-lesson displayed at the start of that language's curriculum page.
- **Migration Results:**
  - Migrated all 62 questions with 100% data preservation across Python, Java, C++, and JavaScript (total of 248 code samples).

## 🚀 Part D: Unlocking C, Go, and Rust (Full 62-Question DSA Content)

### 1. Pre-Flight Language Audit (Step 1)
- Audited `/data/languages/`: JavaScript, Python, Java, and C++ were complete with 62 questions each (374 line explanations per language).
- Diagnosed that C, Go, and Rust were locked due to:
  1. Missing topic code files (`arrays-strings.js`, `hashing.js`, `linked-list.js`, `queue.js`, `stack.js`, `trees.js`).
  2. Hardcoded `available: false` in `meta.js`.
  3. Picker unlock condition requiring a boolean flag rather than checking `questionCount > 0`.
- Documented findings in `LANGUAGE_AUDIT.md`.

### 2. High-Fidelity Content Generation (Step 2)
- Authored complete, idiomatic implementations for **all 62 questions** across 6 topics for **C**, **Go**, and **Rust** (18 new topic modules total, bringing the app total to 434 language-specific question implementations):
  - **C:** Raw pointer arithmetic, explicit struct definitions, heap allocation via `malloc()`, and clean manual memory deallocation via `free()`.
  - **Go:** Idiomatic Go syntax, slice mechanics (`len`, `cap`, reslicing, `make`), pointer vs value semantics, multiple return values, and zero-allocation stack structs.
  - **Rust:** Fearless concurrency & memory safety idioms: `Option<Box<ListNode>>` for single ownership, `Rc<RefCell<TreeNode>>` for shared mutable trees, `VecDeque` for queues, `.take()` for node detaching, and pattern matching.
- Included genuine, language-specific line explanations and memory/idiom notes (no copy-pasting from JavaScript).
- Updated `meta.js` with `available: true` and quickstart how-to-run instructions.
